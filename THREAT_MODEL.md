# Threat model

## Защищаемые данные

- cookie и login databases Chromium/Firefox;
- Telegram `tdata`, Discord LevelDB, Steam config/SSFN;
- DPAPI credentials/protect stores;
- локальные кошельки и данные расширения MetaMask;
- целостность EXE защищаемых клиентов и самой защиты;
- исходящий канал эксфильтрации.

## Покрытые сценарии

| Сценарий | Реакция |
|---|---|
| Неподписанный EXE из Temp/AppData устанавливает TCP | немедленное исходящее firewall-правило и тревога |
| Подмена Telegram/Steam/браузера | сверка SHA-256 и подписи, блок до проверки соединения |
| Чужой процесс читает cookie/tdata/кошелёк | minifilter спрашивает службу до открытия; deny + блок сети |
| Драйвер ещё не установлен | SACL + Security 4663 замечает чтение после открытия и блокирует сеть |
| Отключение профиля Firewall | профиль включается обратно, пользователь получает предупреждение |
| Удаление правила AntiStealer | правило восстанавливается |
| Маскировка под `svchost` вне Windows | высокий риск и блокировка |
| PowerShell/WScript/MSHTA запускает свежий EXE | повышенный риск и блокировка при соединении |

## Намеренно не делается

- нет скрытия процессов/файлов, перехвата клавиатуры, чтения паролей или выгрузки данных;
- нет отключения Secure Boot, Defender, UAC или проверки подписи;
- нет автоматического удаления: только блокировка и восстанавливаемый карантин по решению пользователя;
- нет доверия по одному имени файла;
- minifilter fail-open при недоступной службе, чтобы ошибка защиты не заблокировала загрузку Windows.

## Остаточные риски

- вредоносный код, внедрённый в уже доверенный процесс браузера, выглядит как владелец хранилища;
- администраторский или kernel-level вредонос может остановить службу/драйвер;
- DMA, UEFI/firmware и уязвимый подписанный драйвер находятся вне области проекта;
- токен, уже отправленный злоумышленнику, отзывается только на стороне аккаунта;
- аудит 4663 является обнаружением после факта, поэтому production-режиму нужен подписанный minifilter;
- ложные срабатывания возможны у backup/indexing/security software — разрешение должно выдаваться только конкретному подписанному файлу или SHA-256.

## Требования к production-релизу драйвера

1. Назначенная Microsoft filter altitude.
2. Статический анализ WDK, CodeQL/SDV и Driver Verifier в отдельной VM.
3. Тесты гонок подключения/отключения communication port и тайм-аутов.
4. HLK/attestation signing через Microsoft Hardware Dev Center.
5. Проверка обновления/отката и аварийного удаления без отключения Secure Boot.
